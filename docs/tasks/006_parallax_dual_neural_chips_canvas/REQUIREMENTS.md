# Задача 006: Динамический параллакс-скролл печатной платы и разделение на Облачные (Яндекс GPT / Gemini) и Суверенные On-Premise LLM

> **Дата постановки:** 2026-10-29  
> **Инициатор:** Главный архитектор ИИ-систем  
> **Статус:** Спецификация и проектирование архитектуры  

---

## 1. Бизнес-контекст и проблема текущей реализации

### Текущее состояние:
1. В компоненте `MicroprocessorCanvas.jsx` центральный микропроцессор отрисован статично в верхней части вьюпорта (`cpuY = Math.min(280, height * 0.28)`).
2. Canvas имеет класс `fixed inset-0`. При вертикальном скролле длинного лендинга (Hero ➔ Каталог решений ➔ Схема архитектуры ➔ Цены) координаты чипов и шин остаются неподвижными относительно экрана, из-за чего фон кажется «замороженным» за скользящими текстовыми карточками.
3. Вся интеллектуальная мощь сведена к одной центральной надписи, в которой смешаны облачные и локальные модели.

### Потребность бизнеса и пользователя:
1. **Технологическая отстройка:** Клиенты должны четко видеть на архитектурном фоне два разных независимых вычислительных ядра:
   - **Ядро 1: Облачные модели (Cloud LLM)** — *Яндекс GPT / Gemini Cloud* (минимальная стоимость токена, высокая доступность, ночной саппорт, быстрый ответ).
   - **Ядро 2: Суверенные модели (On-Premise Sovereign Engine)** — *Локальные Qwen 2.5 / Llama 3.3* (периметр заказчика, строго 152-ФЗ / 99-З, коммерческая тайна, первичка, сметы).
2. **Параллакс-динамика микросхем при скролле:**
   - Элементы топологии платы (микросхемы, контактные площадки, шины передачи данных) должны плавно смещаться с коэффициентом параллакса при скролле страницы вниз и вверх.
   - По мере движения пользователя по лендингу перед ним открываются разные специализированные технологические узлы платы (от входа данных в 1С/Битрикс24 через облачный и локальный ИИ-кластеры к базе данных и исполнительным регистрам).
3. **Производительность:** Плавность 60 fps без просадок на мобильных устройствах и Retina-экранах.

## 2. Функциональные требования (FR)

- **FR-01 (Два специализированных процессорных ядра):**
  - Микросхема А: **«ОБЛАЧНЫЕ LLM · CLOUD ENGINE»** (маркировка: *ЯНДЕКС GPT / GEMINI*).
  - Микросхема Б: **«СУВЕРЕННЫЕ LLM · ON-PREMISE»** (маркировка: *QWEN 2.5 / LLAMA 3.3 · 152-ФЗ / 99-З*).
- **FR-02 (Периферийные узлы и шлюзы):**
  - **1С:ПРЕДПРИЯТИЕ** (Шлюз OData / REST).
  - **БИТРИКС24 CRM** (Шлюз вебхуков и сделок).
  - **БАЗА ДАННЫХ** (PostgreSQL / регистры учета).
  - **ОБРАБОТКА СКАНОВ** (Vision OCR Engine).
- **FR-03 (Параллакс-скролл в Canvas):**
  - Отслеживание `window.scrollY`.
  - Применение плавного демпфирования (lerp) для координаты скролла в цикле `requestAnimationFrame`, исключающего рывки.
  - Коэффициент параллакса: `0.3 – 0.4` от физической прокрутки страницы, создающий ощущение глубокого трёхмерного пространства материнской платы под карточками интерфейса.
- **FR-04 (Сохранение интерактивности):**
  - Плавные волновые импульсы продолжают курсировать по шинам данных с учетом смещения скролла.
  - Реакция на наведение курсора мыши корректно пересчитывает координаты чипов и шин относительно проскролленной позиции.

## 3. Критерии приёмки (Definition of Done)

1. [ ] В холсте визуализированы два выделенных нейро-процессора: Облачный кластер (Яндекс GPT / Gemini) и Суверенный локальный On-Premise кластер.
2. [ ] При скролле страницы вниз плата плавно сдвигается, открывая новые слои и чипы, гармонируя с контентом соответствующих секций сайта.
3. [ ] Векторные световые импульсы движутся плавно и без дерганий.
4. [ ] Потребление CPU/памяти остается в пределах нормы, нет лагов при быстром скролле.
5. [ ] `npm run build` проходит без предупреждений и ошибок.
