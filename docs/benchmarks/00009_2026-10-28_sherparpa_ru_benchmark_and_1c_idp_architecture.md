## 2. Архитектура интеграции с 1С: Сквозной ИИ-конвейер первички

На страницах `/raspoznavanie-pervichki-1s-ii-konveyer/` и `/ii-agenty-dlya-1s/` сформулирована эталонная методология, которую **SFTG AI** берет за основу:

### Экономический эффект в цифрах:
- **Сокращение времени ввода накладной на 300–500 строк:** с **45 минут ручной набивки до 20 секунд**!
- **95% стандартных УПД и счетов** обрабатываются полностью автоматически.
- Оставшиеся 5% пограничных строк подсвечиваются оператору/бухгалтеру в удобном окне верификации (*Human-in-the-loop*).
- Высвобождение до **60% рабочего времени** сотрудников бухгалтерии и финотдела.

### 4 шага конвейера IDP + 1C:
1. **Входной шлюз:** автоматический перехват входящих сканов, PDF и файлов из почты, ЭДО (Диадок / СБИС) и сетевых папок.
2. **Нейросетевая нормализация (Sherpa AI Server):**
   - Устранение перекосов сканов, очистка шума.
   - Извлечение многострочных таблиц, ставок и сумм НДС, номеров ГТД.
   - **Матчинг номенклатуры через векторные семантические эмбеддинги (Embeddings):** сопоставление наименования поставщика с позицией внутреннего справочника 1С по смыслу, артикулам и синонимам.
3. **Безопасная интеграция с 1С (Критический принцип):**
   > [!WARNING]
   > **Категорический запрет на доработку ядра конфигурации 1С:**  
   > Попытка переписать типовую конфигурацию 1С для встраивания нейросетей внутрь ядра ломает официальные обновления платформы и создает дыры в безопасности.  
   > **Решение:** Внешний контур общается с 1С **строго через штатный интерфейс OData / REST API / HTTP-сервисы**.
4. **Формирование черновика:** агент создает документ «Поступление товаров и услуг» с готовыми проводками. Бухгалтеру остается нажать одну кнопку проведения.

## 3. Промышленный ИИ и предиктивный ТОиР

На странице `/vnedrenie-ii-na-proizvodstve/` представлен модельный кейс для производственных цехов:
- **Проблема:** Аварийные внезапные остановки станков, задержки поставок запчастей, дорогой экстренный ремонт.
- **Сценарий Sherpa:**
  1. Датчики фиксируют микровибрацию и дисбаланс ротора двигателя станка.
  2. Edge AI определяет предаварийное состояние за 3–4 недели до поломки.
  3. Агент автоматически формирует заявку на заказ ЗИП (запасных частей) в **1С:ERP** и ставит задачу службе главного механика в регламентное окно техобслуживания.
- **Оптический контроль ОТК:** автоматическая отбраковка бракованных деталей на линии машинным зрением.

## 5. Экономика FinOps: Облачные API vs Локальный сервер

На странице `/skolko-stoit-ii-agent-tco-2026-2027/` приведен важнейший финансовый расчет, который мы должны показывать клиентам SFTG AI:

```
[Облачный подход]
Затраты на токены внешних API (OpenAI/Claude): ~450 000 руб./мес.
Риски: Утечка данных, непрогнозируемый рост счетов, блокировки.

[Локальный On-Premise подход]
Покупка GPU-сервера: 1 200 000 руб. (разово)
Локальная квантованная модель (Qwen 2.5 72B / Llama 3.3):
Ежемесячные затраты (электричество + администрирование): ~35 000 руб./мес.
Срок окупаемости сервера: 3.5 – 4 месяца!
```

## 6. Что забираем в SFTG AI из опыта Sherpa RPA

| Решение Sherpa RPA | Как применяем в SFTG AI |
| :--- | :--- |
| **Кейс первички: «с 45 мин до 20 сек»** | Используем этот факт как главный триггер в оффере для финдиректоров и бухгалтерии. |
| **Интеграция строго через OData / REST** | Позиционируем перед IT-директорами безопасность: мы не ломаем типовую конфигурацию 1С и обновления. |
| **Векторный матчинг номенклатуры (Embeddings)** | Включаем в интерактивную демо-песочницу на сайте: показ того, как ИИ матчит кривые названия поставщиков со справочником 1С. |
| **Связка: Вибродатчик -> ИИ -> Заказ ЗИП в 1С:ERP** | Идеальный сценарий для завода «АЛТАЙ ФИЛД» и других производств. |
| **Смета FinOps (сервер за 1.2M окупается за 4 мес)** | Железный аргумент для собственников: почему On-Premise сервер выгоднее облачных подписок. |
